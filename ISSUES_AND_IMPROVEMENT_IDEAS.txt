## PROPOSED IMPROVEMENT
Look. Mouse coords are in screen space, but LLM doesn't know window's position. LLM had to query window offset additionally. We can provide window offset somewhere, like in win_list_hwnd. UI image recognition may be improved by passing to vision analysis cropped area of interest and giving a hint to image-processing LLM request what's on image if it's known what it expected to be. e.g. LLM wants to explore in details left side of Outlook to see only the list of emails to see are there any unread messages, or did ctrl+a worked and all the messages turns selected. Also visual analysis doesn't have its own context and cannot distinguish differences in images passed to it between two different calls (unselected -> selected). Is it a good idea to make separate agent class with separate API-key (e.g. HELPER API-key to never break the KV-cache of main LLM) and special context_manager for it (whatever visual analyzing context would look like)?
Also an agent asks for pixel coordinated in vision analyzing request. But LLM image-recognition is not intended for pixel perfect positioning. I think it's a subject of Phase 3 (Control discovery and UIA)
